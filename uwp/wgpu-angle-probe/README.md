# Experimental wgpu ANGLE probe

This diagnostic is not Horizon and is not a working UWP port. It uses the vendored wgpu-hal 30.0.1 patch to select EGL on UWP, load libEGL.dll using LoadPackagedLibrary, request ANGLE D3D11, and accept a WinRT CoreWindow handle. Non-UWP Windows continues to use WGL. The probe only requests the GL backend.

On this machine `build.cmd` built the x86_64-uwp Rust static library with stable Rust and `RUSTC_BOOTSTRAP=1` using `-Z build-std`. The path in Cargo.toml selects the local wgpu-hal patch. The script requires Visual Studio at the path in the script, Rust source and the 15063 SDK.

`host-build.cmd` is a **non-compliant diagnostic only**: it links the desktop kernel32 import library to resolve UWP-incompatible imports in Rust std. The earlier diagnostic exe linked but failed activation. A separate strict WindowsApp.lib link was subsequently made using the experimental patched std and link checks described in ../rust-std. On x64 and on the Surface Pro X (ARM64), the strict app created its wgpu device and surface, compiled Horizon's actual `screen.wgsl` using its entity bind group layout, and reported a successful clear and present through modern UWP ANGLE's D3D11 backend. The displayed output has not been visually verified. This is still a shader and clear-color probe, not Horizon.

For a runtime experiment, stage the host manifest and assets from ../host/build/package, rename the exe to HorizonUWP.exe, give the manifest a distinct package identity, include matching UWP ANGLE libEGL.dll and libGLESv2.dll plus their dependencies, then register the staged manifest in Developer Mode. The first x64 test used deprecated ANGLE.WindowsStore 2.1.14 binaries solely for diagnosis. Later x64 and ARM64 tests used the modern vcpkg ANGLE builds described in ../host/README.md. No ANGLE binaries are committed here.

Phone compatibility is unverified. Microsoft documents that Windows Phone must import LoadPackagedLibrary from PhoneAppModelHost.dll rather than Kernel32.dll: https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-loadpackagedlibrary . The vendored patch links WindowsApp.lib and has not been checked for the actual ARM32 import mapping or tested on build 15063. The UWP patch is compile-checked on x64 only. Also, wgpu requests OpenGL ES 3; devices exposing only GLES 2 through ANGLE cannot run this path unchanged.
