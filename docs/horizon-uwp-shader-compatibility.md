This audit covers official Horizon `0a875da91dbb0fdcb7ba8c42c11341aa229af51a`, the November 20 UWP product at `5c26a8060c1cf2dce20ee5707e84699ed0879e5c` (patch 0.1.15, client 0.1.17) and the D3D11 fork at `aa7b65c43ef008d0a92d20fcdf9f10fa0883f157`. The matrix records the fixture, source contract, per-profile status, and evidence required to close each case. `C` means source or component evidence only. `H` means an explicit product or engine gate. `P` means partial. `B` means a demonstrated fixture failure. `U` means an unimplemented route. `X` requires adapter or OS evidence, and `?` means the profile or behavior is unknown. `V` requires a functional result for the named case. The three rejection sites are synchronous classic installation, asynchronous classic build and native pack installation. Each returns the same FL9_1 error. The classic interface calls `pack_inputs()` before reaching the asynchronous build gate, which lets atlas preparation fail first on the signed x64 compatibility route. The compatibility predicate is `adapter.get_info().backend == wgpu::Backend::Dx11`. Separating an actual native D3D11 feature level from this product predicate is required before qualifying any higher-tier pack. ## Selection and failure paths


- The game scans `shaderpacks/` under the game directory. A native directory requires `horizon-shaders.toml`, and a native archive uses the `.hshader` extension. Classic directories and ZIPs require `shaders/`. One active selection is persisted as `pickedShaderPack` in `horizon-graphics.txt`. Native packs resolve to `horizon:<id>`, with migration from an older filename selection. The retired `shaderPack` key is ignored. `HORIZON_SHADER_PACK` is a process-level development override. The picker can list a pack before the renderer evaluates it. [Discovery and selection](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/crates/horizon-client-render/src/shader_pack_list.rs#L86-L216) · [Graphics storage](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/crates/horizon-client-render/src/graphics.rs#L963-L978) · [Developer override and loader dispatch](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/crates/horizon-client/src/game/interface/shader_packs.rs#L79-L94)
- Native settings apply immediately. Classic option edits are staged to Apply or screen exit, then written to `shaderpacks/<pack>.txt` as `NAME=value` and trigger a reload. Native settings use stable pack identity and migrate legacy sidecars. With a native pack selected, file stamps are polled about twice a second. A failed stage keeps an already running good version. Invalid or unsupported manifests turn the pack off until corrected. The classic path can skip individual unsupported programs and preserve useful fallbacks, or disable the pack after a terminal load/build failure. [Picker, options and native reload behavior](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/docs/shaders.md#L54-L78) · [Native failure decisions](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/crates/horizon-client/src/game/modding/native_shaders.rs#L191-L350) · [Classic terminal failure](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/crates/horizon-client/src/game/interface/shader_packs.rs#L690-L713)

## Native Shader API 0.2

The schema and Naga checks build engine-composed WGSL. Runtime uses wgpu pipelines, bind groups and explicit world-pass hooks. Runtime pipeline construction catches internal and validation errors, including a device refusing a layout or translation. API 0.1, `[motion]` and BT.2020 primaries are refused as game-runtime capabilities. The latter two can pass the SDK check. The pack can use separate engine/pack alpha coverage and fog, gamma or linear intermediate blending, and the resources declared for its stage. Float frames fall back where required by the device.
