# Horizon Nightly 2026-11-18 UWP port

The candidate uses Horizon commit `0b14f8acfd97fa2c750e42795249dcc981178ca4`, kept by the upstream tag `nightly-source/2026-11-18-0b14f8a`. Patch 0.1.5 targets this commit. Client 0.1.6 carries the UWP host, bridge and platform services. Builder 1.0.4 stages the source and checks the bridge lockfile before building.

The prior port at Horizon `e797c725ad99ef311db216de7f41a2e6593353db` remains available with patch 0.1.4. The previous keyboard and performance results are recorded independently of the Nightly.

This recipe uses resource schema 7 and preparation output version 5. When reusing a framework, use the identity reported by a build of that refreshed resource tree.

## Source assembly

Use the [immutable source ZIP](https://github.com/horizon-rust/horizon/archive/0b14f8acfd97fa2c750e42795249dcc981178ca4.zip), with SHA-256 `1a73fb817549e9b0ec8870b8aec7efd1ea4e274e8be7563411c053aee6ad48ef`. The Builder stages the bundled wgpu ZIP at `third_party/wgpu-dx11` and applies [the upload-shadow patch](../patches/wgpu-dx11/reuse-upload-buffer-shadow.patch). Both inputs are hash-pinned. The product source update lives in [patch 0.1.5](../patches/nightly-2026-11-18/horizon-uwp-0.1.5.patch).

Prepare a local unsigned catalog candidate and client ZIP from a committed product revision. Supply the pinned wgpu ZIP, exact Horizon Git repository and source ZIP, host kits for all four targets and a fresh output path.

```powershell
python tools/prepare_candidate.py --patch-version 0.1.5 `
    --upstream-repo $upstreamRepo --upstream-archive $upstreamZip `
    --wgpu-archive $wgpuZip --host-artifacts $hostKit --output $output
```

For local source validation, the Builder test executable supports `--assemble-candidate UPSTREAM_ZIP PATCH CLIENT_ZIP OUTPUT UPSTREAM_COMMIT`. Release verification still requires the signed catalog. The catalog checked into this repository continues to authorize the published recipes.

## Prepared Minecraft resources

Builder’s download mode uses the preparer from the assembled source. For a manual build, compile `horizon-prepare` from the pinned source and use your own Minecraft 26.3 files. Use a scratch checkout for the exporter output, then verify the prepared directory before packaging it.

```powershell
cargo +1.99.1 build --locked --release -p horizon-prepare --bin horizon-prepare --target-dir $prepareTarget
$preparer = Join-Path $prepareTarget 'release/horizon-prepare.exe'
& $preparer --prepare --complete --root $scratchSource --output $resources `
    --minecraft-dir $minecraftDir --server-jar $serverJar --java-home $javaHome `
    --version-json $versionJson --assets-dir $assetsDir
& $preparer --check --root $scratchSource --output $resources
```

Keep the generated resources and signed private resource APPX outside version control. The resource framework is architecture-neutral. Its identity derives from the paths and file content of the staged resource tree.

## x64 build

Prepare a scratch Rust source copy using `uwp/rust-std/prepare-source.ps1 -Toolchain 1.99.1`. Set `RUSTC_BOOTSTRAP=1`, `__CARGO_TEST_CHANNEL_OVERRIDE_DO_NOT_USE_THIS=nightly` and `__CARGO_TESTS_ONLY_SRC_ROOT` to the patched library directory. Use matching MSVC 14.44.35207, Clang, SDK 10.0.19041.0, the x64 Store link environment and Rust LLD. Builder assigns the staged UWP build an identity that includes the patch version, client version, architecture and upstream commit.

```powershell
$features = 'uwp-dx11-renderer,uwp-dx12-renderer,native-touch-mod,native-device-vibration-mod,uwp-audio,uwp-https,uwp-controller,xaml-shell'
$env:HORIZON_GAME_BUILD_ID = 'mchorizonuwp-0.1.6-patch-0.1.5-x64-0b14f8acfd97fa2c750e42795249dcc981178ca4'
cargo +1.99.1 build --locked --offline --manifest-path uwp/game-bridge/Cargo.toml `
    --features $features --target x86_64-uwp-windows-msvc -Z build-std=std,panic_abort `
    --release --target-dir $targetDir
```

Link the result with `uwp/host/strict-bridge-link.ps1`, including the matching TLS object and dead-import sentinel. Sign testing packages with a separate AppX identity and use fresh LocalState game data. [Mod runtime evidence](mod-runtime-2026-11-18.md) records the content tests, strict-link results for Wasmtime and native SDK constraints.

## Additional targets

Use the matching native host kit for each target. x86 uses `i686-uwp-windows-msvc`, ARM64 uses `aarch64-uwp-windows-msvc` and ARM32 uses `thumbv7a-uwp-windows-msvc`. For ARM32, first run `python uwp/arm32-deps/prepare.py --offline-arm32` in the build snapshot. Copy `uwp/arm32-deps/Cargo.nightly-offline.lock` to that snapshot’s `uwp/game-bridge/Cargo.lock` and pass `--config .local/arm32-windows-sys/patches-offline-arm32.toml` before the Cargo subcommand. Builder performs these steps in its private ARM32 snapshot. The experimental ARM32 profile uses the offline HTTPS implementation.
