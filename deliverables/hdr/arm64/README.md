# Surface Pro X HDR candidate

Ben-Tablet installed the signed isolated ARM64 game. Its LGD0555 internal display reported 8-bit SDR, `hdrSupported=0`, `activeColorMode=0` and SDR white 80 nits. The physical Adreno 680 driver reported 0–100 nits for this output. Windows build 26320 and driver 27.20.2160.0 exposed working native D3D12 FP16/scRGB and 10-bit/PQ composition buffers even with this SDR-only panel. D3D11 FL11_1 preserved an FP16 readback of (−0.25, 1, 4, 1). A device explicitly created at FL9_1 rejected both HDR buffer formats. [Native output and chain measurements](dxgi-native.log)

The build used `tools/build_nightly_runtime.ps1`, locked offline Cargo dependencies, the integrated UWP engine and DX12 HAL overlays, and the newly linked ARM64 host. Its distinct source and build directories were `%TEMP%\mchorizon-hdr-nov20\assembled-arm64`, `target-arm64` and `build-arm64` on Ben-Desktop. SignTool verified the 45,235,141-byte development APPX. It is saved beside this file as `HorizonUWP-HDR-arm64.appx`. [Build receipt](build-receipt.json) · [Candidate SHA-256 and revisions](package.json) · [Signature verification](signature.txt)

The signed APPX was transferred from Ben-Desktop's `%TEMP%\mchorizon-hdr-nov20\package-arm64\HorizonUWP-arm64.appx` to Ben-Tablet's `%TEMP%\MCHorizonUWP-HdrDev-arm64-20261121\HorizonUWP-arm64.appx` over LAN SSH. The signed-in user registered `MCHorizonUWP.HdrDev.arm64_1.0.0.0_arm64__4pd4jeb6snrqw`. SHA-256 checks matched the source APPX and both installed executable payloads. With HDR Auto requested, the signed game activated normally and started its D3D12 game worker. At startup the XAML view reported SDR and the probe configured BGRA8/sRGB. Windows had locked session 1 and suspended all 31 threads of the game process before a world or HUD frame could be recorded. The passive test sent no input and timed out. The isolated test process was closed and the Surface lock released. Game-frame SDR fallback and screenshots still need an unlocked session.
